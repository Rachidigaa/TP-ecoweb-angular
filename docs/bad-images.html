Mauvaise pratique : thumbs générées par mise à l'échelle CSS d'une grande image

Thumbnail non responsive (mauvais)

Image source (1920×1080, ~200KB) utilisée comme vignette 70×60 : téléchargement inutilement lourd.

<img id="thumb-bad" src="/assets/images/large-photo-1920x1080.png" alt="Vignette mal optimisée">

Mauvaise pratique : pas de srcset ni de picture

Sans srcset, le navigateur télécharge le plus grand fichier et le met en cache pour toutes les tailles d'écran.

Bonne pratique (exemple commenté)

Utiliser srcset pour fournir des alternatives et sizes pour informer le navigateur :

<img src="image_small.png" alt="" width="70" height="60"
     srcset="image_small.png 70w, image_medium.png 640w, image_large.png 1920w"
     sizes="(max-width: 640px) 70px, 350px">

Conseils

  • Générez plusieurs variantes (webp/avif + different sizes) et fournissez un srcset.
  • Définissez width & height ou CSS pour réserver l'espace et réduire le Cumulative Layout Shift (CLS).
  • Servez les images optimisées côté serveur (compression, conversion en WebP/AVIF).
  • Comparez poids & pixels avec yellowlab.tools ou Lighthouse.

Mauvaise pratique : préférer les bitmaps quand un SVG suffit

Les formats matriciels (PNG, JPG) sont parfois beaucoup plus lourds qu'un SVG équivalent. Préférez les icônes SVG ou les glyphes quand c'est possible.

Comparaison (exemple)

Même icône :

  • Bitmap brut (ex : BMP) : ~118 Ko
  • JPEG (qualité 90%) : ~6.5 Ko
  • PNG (optimisé) : ~3.8 Ko
  • SVG (minifié) : ~0.7 Ko

Mauvais exemple (bitmap utilisé pour une icône simple) :

<img src="/assets/images/icon-example.png" alt="icône bitmap" width="24" height="24">

Bonne pratique (SVG léger, vectoriel et infiniment redimensionnable) :

<img src="/assets/images/icon-example.svg" alt="icône SVG" width="24" height="24">

Astuce : minifiez vos SVG avec SVGOMG pour réduire encore le poids.

Démo

Dans la plupart des cas, remplacez vos petites images bitmap par un SVG ou une font d'icônes pour réduire les transferts et gagner en qualité d'affichage.
