Modifier le DOM en le traversant (mauvaise pratique)

Modifier la structure du DOM pendant l'itération peut créer des boucles infinies ou amplifier le coût en CPU (collections vivantes). Évitez d'ajouter ou de retirer des éléments directement pendant le parcours; collectez d'abord les cibles, puis modifiez-les.

Exemple dangereux (native, getElementsByTagName renvoie une collection vivante)

// Mauvais : getElementsByTagName renvoie une collection vivante -> l'ajout d'éléments
// augmente la longueur pendant l'itération et peut rendre la boucle infinie
var links = document.getElementsByTagName('a');
for (var i = 0; i < links.length; i++) {
  if (links[i].classList.contains('extlink')) {
    var a = document.createElement('a');
    a.className = 'extlink';
    document.body.appendChild(a); // la collection 'links' grandit -> risque d'infini
  }
}

Exemple dangereux (jQuery)

// Mauvais : modification du DOM pendant la boucle
$('a.extlink').each(function(index, el) {
  $(el).after('dup');
});

Bonne pratique

// Bon : collecter d'abord, puis modifier
var toUpdate = [];
var links = document.querySelectorAll('a.extlink'); // NodeList statique
links.forEach(function(el) { toUpdate.push(el); });
toUpdate.forEach(function(el) { el.setAttribute('rel', 'external nofollow'); });

Conseil : préférez les sélections statiques (querySelectorAll), stockez les éléments dans un tableau temporaire et appliquez les modifications ensuite en une seule passe pour éviter les itérations prolongées et les effets de bord.
